# kempower-zero-human

LahtiES Energy Tech Hackathon 2026 · Kempower Challenge
**零连续人力充电网络**的设计、核算与可复现仿真。

## 这是什么

回答赛题那句话：*如果人类不再被允许持续运营和维护充电网络，你会怎么重新设计？*

核心结论：**21 个连续 FTE 里，14.5 个卡在"谁去插枪"这个物理动作上，不是算法问题。**
解决办法不是造机器人，而是让每个车位都有枪，让本来就在现场的司机自己插。

完整设计见 [`ZERO_HUMAN_DESIGN.md`](ZERO_HUMAN_DESIGN.md)。

## 快速运行

```bash
python run_s1.py
```

只需 Python 3.10+，无第三方依赖。

## 输出什么

以 S1 公交北场站 2026-11-12 夜间为例（23 辆车、12 把枪、1,080 kW）：

| 指标 | 真实基线 | 零人化方案 |
|---|---:|---:|
| 人工挪车 次/夜 | 9 | **0** |
| 欠电发车 辆 | 4 | **0** |
| 全队充满时刻 | 06:30 | **02:31** |
| 连接点 | 12 | 24 |

## 方法说明

**基线不靠模型猜。** 场景 A 直接读 `sessions_baseline.csv` 里 11-12 夜间的真实充电会话，
欠电车辆与 `baseline_kpis.csv` 的官方统计（4 辆）一致。

**反事实才用仿真。** `src/edf_packer.py` 建模了三个容易被忽略的物理事实：

1. **恒压段衰减** —— SoC > 80% 后车端受电功率骤降，这是充电后段变慢的根本原因；
2. **机柜故障是掉枪，不是全体降速** —— C1-3 停机等于挂在它上面的 4 个连接点直接失电；
3. **换位要 8 分钟** —— 取自 `operations_log.csv` 的 `staff_minutes`，这期间枪位空转。

分配算法是**注水式**的：按「剩余电量 / 剩余时间」定权重，被恒压段卡住的车拿走它能吃的部分，
剩余功率再分给没被卡住的车。等价于 EDF 的连续功率版本。

## 数据来源

`data/` 下全部为赛题官方合成数据（`README.md` 注明 *All data is synthetic*），
未做任何修改。外部数字（21 FTE、设备单价）均引自赛题材料与 Kempower 开营演讲。

## 边界

本设计做不到字面意义的零人。设备会坏到降级也救不了的程度（机柜整体烧毁、车辆撞坏设备），
这时需要人。设计目标是：**没有任何一个人需要为这个网络的日常运转而存在。**
残留约 1.0 FTE，全部是排班表上的季度巡检，不是凌晨被叫起来的应急。
